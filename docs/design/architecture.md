# 总体架构

TwinGuide 按公开接口、配置、阶段编排、几何计划、Blender 实体化和独立验证分层。

## 公开接口

顶层 `twin_guide` 只导出 `CaseConfig`、`generate_guide()`、
`run_generation_process()`、`validate_guide()` 及对应结果类型。锚点选择器、网格
构造器和算法参数属于内部实现，不构成兼容承诺。

## 配置与编排

`twin_guide.config` 从一份病例 YAML 生成不可变 `CaseConfig`。七阶段控制器只按顺序
调用阶段入口并把类型化结果写入 `GenerationContext`；未配置的可选阶段以
`skipped` 记录。

## 几何层

牙位识别、观察窗、锚点、按压梁和连续连接梁分别返回不依赖最终 Blender 对象的
计划结果。阶段之间只传递公开结果类型，不调用其他阶段的私有函数。当前只有 FDI
轴扫观察窗和连续框架两套正式几何入口，不存在运行时策略分派。

## Blender 层

`twin_guide.blender` 消费几何计划，负责 STL 读写、切割体、曲线扫掠、布尔运算、
体素融合、导孔复切、渲染和导出。该层不得重新读取病例语义或选择算法。

## 验证层

`validate_guide()` 使用相同配置和几何计划重建检查基准，再独立检查最终 STL 的拓扑、
导管保留、连接梁、按压梁、导孔和观察窗。验证不修改待检查模型。

## 数据边界

业务代码和非患者测试夹具位于仓库内；真实病例 STL、Blend、完整病例 YAML 和参考
结果位于同级 `../data`。单元测试不得要求该目录存在，集成和端到端测试在缺失外部
数据时明确跳过。
